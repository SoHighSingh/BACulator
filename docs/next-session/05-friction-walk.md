## Detail on the user's own list

- **Dialogs close statically:** confirmed for every Radix sheet (gone within one frame, 0 animations); the overlay has no fade either way; the big-graph modal is the only thing that animates out (200ms) and it uses a different language (zoom). `src/components/night/Sheet.tsx` has only `sheet-up`.
- **Adding a drink is a nightmare / slider glitchy:** the size step opens pre-scrolled (#4), the Earlier… slider inserts and auto-scrolls (#12), the −/+ step and labels change per tap, chips and slider fight over the same state (a chip tap collapses the slider), and the "+" quick add can't take a time, so "earlier" always needs the long path.
- **"Estimate only. Bodies and pours vary."** also sits in the details sheet as two separate lines ("The range is wide because bodies and pours vary." and "Estimate only. It can't tell you…"); three disclaimers in two places.
- **Voice barely works:** besides recognition quality, failure is silent (#8) and the mic key is hidden under 360px while the label still promises "say".
- **"Counted" redundant with the tab:** also "Now · about 0.10" vs the headline, Peak/Back to zero vs the sheet (#18).
- **Back to zero + back to 0.05 as one row:** the model has `backToZero` as a range; there is no 0.05 crossing in `NightModel` yet; the sheet rows and the Numbers card both build their own row lists, so the one row should live in one place (the sheet).
- **Small extra decimal:** the landing's maths card currently shows four decimals raw (`0.1023`); whatever the night screen adds must stay rounded up.
- **Added a drink, then had to edit it to set its time:** the row "+" and the recent rows log at "now" only; the time step only exists behind the row tap (4+ taps).
- **Edit changed another drink's time:** could not reproduce in dev (no-op Save changed 0 rows; dev saves by id). In the real app the edit is a remove + add that creates a new drink id and a notice that says "Added" (#6); worth testing signed-in with two identical drinks, since `pickRepeatAndRecents` and the recents key on `name|standards`, not id.
- **Visible scrollbar:** none detected by the DOM probe in headless mobile Chrome (overlay scrollbars); on desktop Chrome `.app-main` and the sheet's `overflow-y-auto` div will show classic scrollbars; `scrollbar-width: none` / `::-webkit-scrollbar { display:none }` on `.app-main` and `.sheet .overflow-y-auto` fixes it.
- **Tab and details sheet redesign:** see #18, #11, #19.
